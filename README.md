# QAxRayTest

Платформа безопасного базового тестирования сайтов и API.
Вы вводите адрес, запускаете стандартный набор проверок и получаете понятный результат:
какие проверки пройдены, где есть проблема и что не удалось проверить.

> Статус: ранняя версия (Sprint 2 завершён). Работают 17 из 25 запланированных проверок:
> доступность и HTTP, структура по исходному HTML, ссылки и навигация, API по `GET`-путям.
> Браузерные проверки запланированы на Sprint 3. План: [docs/checklist/checklist-v1.md](docs/checklist/checklist-v1.md).

**Используйте только на сайтах, которые вы вправе проверять** (свои, тестовые стенды,
`https://example.com`). Приложение выполняет только безопасные `GET`-запросы
и блокирует адреса внутренних сетей.

## Что умеет сейчас

| ID | Проверка |
|---|---|
| QC-001 | Главная отвечает в пределах тайм-аута |
| QC-002 | Статус ответа успешный (2xx) |
| QC-003 | Используется HTTPS |
| QC-004 | Нет цикла перенаправлений |
| QC-005 | Content-Type главной страницы: HTML |
| QC-006 | У страницы есть title |
| QC-007 | Страница не пуста (видимый текст) |
| QC-008 | Базовая структура HTML: html, head, body, lang |
| QC-011 | Ссылки имеют корректный href (до 50 ссылок) |
| QC-012 | Внутренние ссылки доступны (до 10, только `GET`, только тот же домен) |
| QC-013 | Основная навигация найдена |
| QC-020 | Базовый адрес API отвечает (если указан) |
| QC-021 | Указанные GET-пути возвращают ожидаемый статус (по умолчанию 200) |
| QC-022 | Content-Type ответов API: JSON |
| QC-023 | JSON в ответах API разбирается |
| QC-024 | Обязательные поля из документации (OpenAPI/Swagger JSON) есть в ответах |
| QC-025 | Неизвестный путь API обрабатывается предсказуемо (если указан адрес) |

Статусы результата: `PASSED`, `FAILED`, `WARNING`, `SKIPPED`, `BLOCKED`
(смысл каждого: [ADR-0002](docs/decisions/0002-statuses-and-stability.md)).

## Быстрый старт

Нужен Python 3.12 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

### Консоль

```bash
python -m app.cli https://example.com
```

Проверки API необязательны. Они выполняют только безопасные `GET` по указанным путям:

```bash
python -m app.cli https://example.com \
  --api-docs https://api.example.com/openapi.json \
  --api-base https://api.example.com \
  --api-path /health --api-path /items \
  --api-expect /health=201
```

`--api-expect ПУТЬ=СТАТУС[,СТАТУС]` задаёт ожидаемый статус пути (по умолчанию 200).
В веб-форме то же пишется в строке пути: `/health | 201` или `/items | 200,404`.
Документация читается только в формате JSON (OpenAPI 3.x или Swagger 2.0).

Код возврата: `0` — нет `FAILED` и `BLOCKED`; `1` — есть `FAILED` или `BLOCKED`;
`2` — адрес или параметры отклонены.

### Настройки

Лимиты HTTP-клиента задаются переменными окружения `QAXRAY_*` (список с границами в
[.env.example](.env.example)), например `export QAXRAY_HTTP_TIMEOUT=15`. Значения вне границ
отклоняются при запуске. Защита от запросов во внутренние сети не настраивается.

### Веб-интерфейс

```bash
python -m flask --app "app.web:create_app" run
```

Откройте http://127.0.0.1:5000, введите адрес, подтвердите право на тестирование
и нажмите «Запустить проверки». Режим `--debug` включайте только на своём компьютере.

## Живые тесты (необязательные)

Проверка приложения на настоящих адресах. По умолчанию выключены, в CI не запускаются.
Список целей лежит в JSON-файле **вне репозитория** (формат: `tests/live/targets.example.json`);
для каждой цели можно указать ожидаемые статусы проверок. Имена целей лучше писать латиницей:
pytest показывает кириллицу в именах тестов экранированной.

```bash
QAXRAY_LIVE=1 QAXRAY_LIVE_TARGETS=/путь/к/targets.json python -m pytest tests/live -v
```

Один запуск на цель, пауза 1,5 с между целями, только безопасные `GET`.
Используйте адреса, которые вы вправе проверять.

## Тесты и качество

```bash
python -m pytest
python -m ruff check . && python -m ruff format --check .
python -m mypy app scripts
python scripts/check_content.py
```

Тесты не обращаются к сети: HTTP и DNS подменяются заглушками.
Те же проверки запускает CI (`.github/workflows/ci.yml`).

## Архитектура

```
app/
  schemas/    модели данных: статус, результат проверки, отчёт
  core/
    ports.py      контракты (HTTP-клиент, ошибки) — от них зависят проверки
    security/     политика адресов (защита от SSRF)
    checks/       контракт проверки, контекст запуска, каталог, сами проверки
    execution/    исполнитель: изоляция сбоев, статус BLOCKED
  adapters/http/  безопасный HTTP-клиент на requests
  services/       сценарий «адрес → отчёт»
  web/            Flask: форма и страница результатов
  cli.py          консольный запуск
  bootstrap.py    сборка настоящих компонентов в одном месте
```

Принципы:
- `core` не знает про Flask, requests и Selenium: зависимости идут от контрактов.
- Новая проверка — один класс и одна строка в каталоге; исполнитель не меняется.
- Сбой одной проверки не останавливает запуск и превращается в `BLOCKED`.
- Решения зафиксированы в [docs/decisions](docs/decisions).

## Безопасность

- Разрешены только `http` и `https`; адрес проверяется до первого запроса.
- Блокируются loopback, частные, link-local, служебные и многоадресные диапазоны,
  в том числе IPv4 внутри IPv6; проверяются все IP-адреса из DNS-ответа.
- Каждое перенаправление проверяется заново; их число ограничено.
- Лимиты: тайм-аут, размер читаемого ответа, число повторов (только при сетевых сбоях).
- Известные ограничения: [ADR-0003](docs/decisions/0003-dns-rebinding-and-known-risks.md).
