# QAxRayTest

Платформа безопасного базового тестирования сайтов и API.
Вы вводите адрес, запускаете стандартный набор проверок и получаете понятный результат:
какие проверки пройдены, где есть проблема и что не удалось проверить.

> Статус: версия `0.1.1` (MVP). Работают все 25 проверок: доступность и HTTP, структура по исходному HTML, ссылки и
> навигация, API по `GET`-путям и браузерные проверки (изображения, переполнение, имена кнопок, метки полей,
> клавиатура, вход и регистрация без ввода данных). Есть веб-форма и консоль, фоновые запуски с остановкой, черновики
> bug report и результаты для Allure. Подробности: [CHANGELOG.md](CHANGELOG.md), чек-лист проверок:
> [docs/checklist/checklist-v1.md](docs/checklist/checklist-v1.md).

**Используйте только на сайтах, которые вы вправе проверять** (свои, тестовые стенды,
`https://example.com`). Приложение выполняет только безопасные `GET`-запросы
и блокирует адреса внутренних сетей. Секреты (токены, ключи, пароли, `Authorization`, `Cookie`) маскируются в
результатах, на страницах, в консоли и в журналах ([ADR-0011](docs/decisions/0011-secret-redaction.md)).

## Быстрый старт для пользователя

Приложение работает на вашем компьютере: сайт открывается в браузере, но запускается из терминала. Нужно один раз
выполнить несколько команд. Программировать не нужно.

**1. Установите Python 3.12 или новее** с [python.org](https://www.python.org/downloads/). Проверка: в терминале
`python3 --version` (на Windows `py --version`). Терминал на Mac: приложение «Терминал», на Windows: «Командная строка».

**2. Скачайте проект.** На странице [релизов](https://github.com/ikqavscode-afk/QAxRayTest/releases) выберите последний релиз
и скачайте «Source code (zip)», распакуйте архив. В терминале перейдите в распакованную папку (команда `cd` и путь к папке).

**3. Установите (один раз).**

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
```

На Windows вместо второй команды: `.venv\Scripts\activate`.

**4. Запустите сервер.**

```bash
python -m flask --app "app.web:create_app" run
```

Когда в терминале появится строка `Running on http://127.0.0.1:5000`, откройте этот адрес в браузере. **Не закрывайте
терминал, пока пользуетесь приложением:** закроете его, и страница перестанет открываться (в браузере будет
`ERR_CONNECTION_REFUSED`). Остановить сервер: `Ctrl+C` в терминале.

**5. Введите адрес сайта**, поставьте галочку «Я подтверждаю, что имею право тестировать этот сайт» и нажмите
«Запустить проверки». Результат появится на странице, кнопки внизу скачивают черновики bug report и результаты для Allure.

**В следующий раз** достаточно открыть терминал в той же папке и выполнить `source .venv/bin/activate`, затем команду
запуска из шага 4.

### Если не открывается

- **Порт 5000 занят (часто на Mac).** Системная служба AirPlay на macOS использует порт 5000, и сервер не стартует или
  страница не открывается. Запустите на другом порту и откройте соответствующий адрес:

  ```bash
  python -m flask --app "app.web:create_app" run --port 5050
  ```

  Адрес тогда `http://127.0.0.1:5050`.
- **`ERR_CONNECTION_REFUSED`:** сервер не запущен или терминал закрыт. Повторите шаг 4.
- **Команда `python3` или `pip` не найдена:** Python не установлен или терминал открыт до установки; откройте терминал заново.
- **Chrome не нужен.** Без него браузерные проверки получают `SKIPPED`, остальные работают. Если Chrome установлен, они
  выполнятся.

### Безопасность при запуске у себя

Запускайте только командой выше: она слушает адрес `127.0.0.1`, то есть доступна только вам. **Не добавляйте `--host 0.0.0.0`**
(откроет приложение всей вашей сети) и **`--debug`** (даёт выполнять код через страницу). Проверяйте только свои сайты и
те, на тестирование которых у вас есть разрешение.

## Быстрый старт

Нужен Python 3.12 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

### Консоль

```bash
python -m app.cli https://example.com
```

Проверки API необязательны. Они выполняют только безопасные `GET` по указанным путям:

```bash
python -m app.cli https://example.com \
  --api-docs https://api.example.com/openapi.json \
  --api-base https://api.example.com \
  --api-path /health --api-path /items \
  --api-expect /health=201
```

`--api-expect ПУТЬ=СТАТУС[,СТАТУС]` задаёт ожидаемый статус пути (по умолчанию 200).
В веб-форме то же пишется в строке пути: `/health | 201` или `/items | 200,404`.
Документация читается только в формате JSON (OpenAPI 3.x или Swagger 2.0).

Код возврата: `0` — нет `FAILED` и `BLOCKED`; `1` — есть `FAILED` или `BLOCKED`;
`2` — адрес или параметры отклонены.

### Отчёты

После завершения или остановки запуска на странице результатов доступны файлы (кнопки блока «Отчёты»):

- **Черновики bug report** (Markdown и JSON): по одному на каждую проверку `FAILED`, со статусом «не подтверждено»
  и пустым приоритетом; файл появляется только если есть `FAILED`.
- **Результаты для Allure** (ZIP): распакуйте в каталог и откройте командой `allure serve КАТАЛОГ`
  ([ADR-0012](docs/decisions/0012-allure-results.md)).

Секреты в файлах замаскированы. Результаты хранятся в памяти процесса не более часа.

### Настройки

Лимиты HTTP-клиента задаются переменными окружения `QAXRAY_*` (список с границами в
[.env.example](.env.example)), например `export QAXRAY_HTTP_TIMEOUT=15`. Значения вне границ
отклоняются при запуске. Защита от запросов во внутренние сети не настраивается.

### Браузер

Для браузерных проверок нужен установленный Chrome (без него они получают `SKIPPED` с понятной причиной, а
остальные проверки работают: [ADR-0008](docs/decisions/0008-missing-chrome-is-skipped.md)). Драйвер при первом запуске загружает Selenium
Manager. Chrome ходит в сеть только через локальный прокси-сторож, который пропускает лишь публичные
адреса ([ADR-0007](docs/decisions/0007-browser-and-navigation-guard.md)). Проверка с настоящим Chrome:

```bash
QAXRAY_BROWSER=1 python -m pytest tests/browser -v
```

### Веб-интерфейс

```bash
python -m flask --app "app.web:create_app" run
```

Откройте http://127.0.0.1:5000, введите адрес, подтвердите право на тестирование
и нажмите «Запустить проверки». Проверки выполняются в фоне: на странице результата виден прогресс, а кнопка «Остановить запуск» прекращает
проверки (одновременно допускается 2 запуска). Результат открывается по своему адресу (`/runs/…`), его можно
обновлять и открывать повторно: проверки заново не запускаются. У каждой проверки своя страница с ожидаемым и
фактическим результатом, причиной и доказательствами (`/runs/…/checks/QC-001`). Результаты хранятся 1 час (не более
50 запусков),
см. [ADR-0009](docs/decisions/0009-run-storage-and-prg.md). Режим `--debug` включайте только на своём компьютере.

## Живые тесты (необязательные)

Проверка приложения на настоящих адресах. По умолчанию выключены, в CI не запускаются.
Список целей лежит в JSON-файле **вне репозитория** (формат: `tests/live/targets.example.json`);
для каждой цели можно указать ожидаемые статусы проверок. Имена целей лучше писать латиницей:
pytest показывает кириллицу в именах тестов экранированной.

```bash
QAXRAY_LIVE=1 QAXRAY_LIVE_TARGETS=/путь/к/targets.json python -m pytest tests/live -v
```

Один запуск на цель, пауза 1,5 с между целями, только безопасные `GET`.
Используйте адреса, которые вы вправе проверять.

## Тесты и качество

```bash
python -m pytest
python -m ruff check . && python -m ruff format --check .
python -m mypy app scripts
python scripts/check_content.py
```

Тесты не обращаются к внешним сайтам: HTTP и DNS подменяются заглушками, сквозные тесты используют имитированную
сеть и заглушку браузера (`tests/integration`), одному тесту нужен только локальный сервер на `127.0.0.1`.
Те же проверки запускает CI (`.github/workflows/ci.yml`), браузерные тесты идут отдельным заданием.

## Архитектура

```
app/
  schemas/    модели данных: статус, результат проверки, отчёт, цель и запуск
  core/
    ports.py      контракты (HTTP-клиент, ошибки) — от них зависят проверки
    security/     политика адресов (защита от SSRF), маскирование секретов
    checks/       контракт проверки, контекст запуска, каталог, сами проверки
    execution/    исполнитель: изоляция сбоев, статус BLOCKED
    reports/      черновик bug report и результаты для Allure
    browser*.py   порт браузера и сессия с лимитами
  adapters/
    http/         безопасный HTTP-клиент на requests, соединение с проверенным IP
    browser/      Selenium, прокси-сторож навигации, поиск Chrome
  services/       запуск, фоновое выполнение и остановка, хранилище запусков, ограничитель частоты, выгрузка отчётов
  web/            Flask: форма, результаты, скачивание, защита от CSRF
  cli.py          консольный запуск
  bootstrap.py    сборка настоящих компонентов в одном месте
```

Принципы:
- `core` не знает про Flask, requests и Selenium: зависимости идут от контрактов.
- Новая проверка — один класс и одна строка в каталоге; исполнитель не меняется.
- Сбой одной проверки не останавливает запуск и превращается в `BLOCKED`.
- Решения зафиксированы в [docs/decisions](docs/decisions).

## Безопасность

- Разрешены только `http` и `https`; адрес проверяется до первого запроса.
- Блокируются loopback, частные, link-local, служебные и многоадресные диапазоны,
  в том числе IPv4 внутри IPv6; проверяются все IP-адреса из DNS-ответа.
- Каждое перенаправление проверяется заново; их число ограничено. Соединение идёт только с IP, проверенным политикой
  (защита от DNS rebinding, [ADR-0015](docs/decisions/0015-pinned-connection.md)); прокси из окружения не используются.
- Проверяется заголовок `Host`, ответы несут строгие защитные заголовки (CSP и другие), запуск ограничен по времени, есть
  общий предел запусков на весь сервис ([ADR-0016](docs/decisions/0016-web-hardening-and-deployment.md)).
- Частота запусков ограничена на один адрес клиента и по числу одновременных запусков ([ADR-0014](docs/decisions/0014-rate-limiting.md)).
- POST-запросы (запуск и остановка) защищены токеном и проверкой Origin ([ADR-0013](docs/decisions/0013-csrf-protection.md)).
- Лимиты: тайм-аут, размер читаемого ответа, число повторов (только при сетевых сбоях).
- Известные ограничения: [ADR-0003](docs/decisions/0003-dns-rebinding-and-known-risks.md).

## Публикация и ограничения версии 0.1.1

Приложение рассчитано на запуск на своём компьютере или на доверенном стенде. Перед открытым доступом учтите:

- запускайте по HTTPS и задайте `QAXRAY_COOKIE_SECURE=1`, иначе cookie защиты формы пойдёт и по `http://`; укажите своё
  имя в `QAXRAY_ALLOWED_HOSTS`;
- за обратным прокси задайте `QAXRAY_TRUSTED_PROXIES` (число прокси), иначе все пользователи окажутся «одним клиентом»;
- Chrome на сервере изолируйте (контейнер без доступа во внутренние сети, лимиты ресурсов) или выключите браузерные
  проверки; полный список требований: [ADR-0016](docs/decisions/0016-web-hardening-and-deployment.md);
- у себя запускайте только командой `flask run` (адрес `127.0.0.1`): не используйте `--host 0.0.0.0` и `--debug`;
- один процесс: запуски, счётчики частоты и ключ защиты формы хранятся в памяти и пропадают при перезапуске;
- постоянного хранения отчётов и учёта пользователей нет;
- публичный сервис «проверять любые адреса» выпускать нельзя: концепция требует собственной демо-цели или явно
  разрешённого списка адресов.

## Пример запуска

Реальный прогон (2026-11-08) по `https://example.com` без API: `PASSED` 11, `WARNING` 1 (нет навигации), `SKIPPED` 13
(нет изображений, кнопок, форм и API; причина указана у каждой проверки), `FAILED` и `BLOCKED` 0, код возврата 0.
С документацией и путями публичного демо-API (Petstore) проверки API дают 16 `PASSED` и 2 `WARNING`
(расхождение с документацией по QC-024 и ещё одно предупреждение), код возврата 0. Через веб-форму тот же запуск
завершается за несколько секунд, а архив Allure скачивается кнопкой «Результаты для Allure (ZIP)».
