# Sprint 3. Браузер: основа. Итоги и ретроспектива

Период: 2026-11-07. Статус: завершён. План: [sprint-03-plan.md](sprint-03-plan.md).

## Цель спринта

Безопасно открыть страницу в браузере и выполнить ограниченные проверки структуры и доступности,
не нарушая правил стабильности и политики адресов. **Цель достигнута.**

## Обзор спринта (демонстрация)

Полный профиль из 22 проверок выполняется за 4–10 секунд. На `books.toscrape.com`: 15 `PASSED`, 7 `SKIPPED`
(20 изображений, 10 внутренних ссылок, 20 кнопок, обход Tab до 20 элементов). На `saucedemo.com` проверка QC-016
нашла **реальный дефект доступности**: у полей входа и кнопки нет видимого индикатора фокуса (подтверждено вручную
по стилям и снимку экрана).

## Что прошло хорошо

- **Живые проверки с настоящим Chrome находили дефекты, которых не видели заглушки:** окно 375 px на деле было
  500 px (минимум headless-Chrome), ошибка сертификата выглядела как обычная страница, `placeholder`-метки,
  `saucedemo` без индикатора фокуса. Каждая находка закреплена автотестом.
- Безопасность браузера доказана экспериментом: JavaScript страницы пытался обратиться к реальному локальному
  серверу, сервер получил **0 соединений** (прокси-сторож), и это же проверяется в CI.
- Схема «проба возвращает факты, вердикт в проверке на Python» позволила тестировать все 7 проверок на заглушке
  без браузера и держать тексты страниц и параметры запросов вне отчётов.
- Первый запуск браузерного задания на GitHub (Linux) сразу зелёный.
- Ритм коммитов (задача = коммит, публикация пачкой) сработал: 4 публикации, ни одного красного CI.

## Что мешало

- Текстовые замены в тестах ломались после `ruff format` (формат переписывал строки): три раза пришлось править
  вручную. Урок: менять файлы по структуре, а не по точной строке, и сначала запускать формат.
- Мелкие ошибки в тестах: формат `QC-00{n}` для числа 10, слишком точные ожидания источника имени в Chrome.
- Прогон по недоступному сайту показался «зависанием»: вывод был буферизован. Причина была внешняя (сайт недоступен),
  но диагностика заняла время; теперь живые скрипты запускаются с немедленным выводом.
- Недоступный сайт стоит около 50 секунд (HTTP-повторы, затем браузер).

## Уроки

1. Любую браузерную проверку нужно подтверждать на настоящем Chrome: заглушка не знает его особенностей.
2. Эвристику сначала проверять на реальных страницах и вручную, чтобы отличить находку от ложного срабатывания.
3. Проба, которая управляет страницей (Tab), получает жёсткие меры безопасности и тест на них заранее.

## Технический долг и риски

- Chrome теперь нужен профилю по умолчанию: без него браузерные проверки дают `BLOCKED`, а консоль код 1.
  Нужно решение владельца продукта (см. Sprint 4).
- Недоступный сайт стоит около 50 секунд (PB-068: не запускать браузер, если главная недоступна по HTTP).
- Страница перезагружается при смене ширины окна: честно, но дольше.
- Сетевой сбой на одном `GET`-пути блокирует проверки по путям целиком (PB-045).
- Внутри HTTPS-туннеля сторож не видит метод запроса ([ADR-0007](../decisions/0007-browser-and-navigation-guard.md)).
- Прочее из [ADR-0003](../decisions/0003-dns-rebinding-and-known-risks.md): CSRF, ограничение частоты, DNS rebinding
  для HTTP-клиента, синхронный запуск (устраняется в Sprint 4).
