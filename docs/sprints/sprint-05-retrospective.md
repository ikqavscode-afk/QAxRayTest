## Обзор спринта (демонстрация)

- Секреты из адреса и заголовков не видны ни на странице, ни в JSON статуса, ни в консоли, ни в журналах, ни в
  скачанных файлах (проверено «канарейками» на каждом пути вывода).
- Для каждого `FAILED` формируется черновик «не подтверждено»; разметка из ответов сайта экранируется.
- Архив Allure собран настоящим Allure Report, статистика совпала с ожидаемой (failed, broken, skipped, passed).
- Сетевой сбой на одном API-пути больше не блокирует остальные: QC-021 показывает результат по каждому пути.
- Страница запуска получила блок «Отчёты»; на 375 px кнопки по 44 px, прокрутки вбок нет.
- Три сквозных сценария идут на настоящих проверках с имитированной сетью и заглушкой браузера: полный запуск и отчёты,
  остановка посреди работы, запрещённый адрес и отсутствие Chrome.

## Что прошло хорошо

- Все 28 SP, ни одного красного CI на опубликованных коммитах.
- Раннее решение о границе (`Redactor` на границах, а не в каждой проверке) сделало отчёты безопасными «по
  построению»: новые пути вывода только подключаются к уже замаскированным данным.
- Безопасность проверялась враждебными входами и «канарейками», а не только примерами.
- Проверка Allure реальным генератором сразу подтвердила соответствие формату.
- Хранилище за интерфейсом `RunStore` позволило добавить выгрузку без изменения проверок.

## Что мешало

- **GitHub Push Protection** заблокировал пуш из-за выдуманного токена в тесте (`xoxb-…`): сканер не отличает
  настоящие секреты от придуманных. Исправлено сборкой строк из частей, правилом в `check_content.py` и тестом-стражем;
  блокировка не обходилась.
- **Квадратичное время** двух правил маскирования (ReDoS) обнаружили только враждебные входы (2,5 с и 8 с на 60 тысячах
  символов); исправлено привязкой к началу схемы и ограничением длины.
- «Запушил» снова не означало «ушло»: один раз коммиты остались локально.
- Текстовые замены в тестах после `ruff format` снова ломались.
- Часть кода сначала писалась и только потом гонялась на красный: правило «сначала красный» нужно соблюдать строже.
- Длинная сессия: пришлось восстанавливать контекст по документам.

## Уроки

1. Придуманные «секреты» в тестах тоже срабатывают у сканеров: собирать их из частей с самого начала.
2. Любое новое регулярное выражение сразу проверять на враждебных входах, а не примерами.
3. Публикацию подтверждает сравнение `origin/main` с `HEAD`, а не слова.
4. Сквозные тесты надёжнее с имитированными краями (сеть, браузер, разрешение имён), чем с живыми сайтами.
5. Безопасность на границах дешевле и надёжнее, чем в каждой проверке.

## Технический долг и риски

- Нет защиты формы и остановки от CSRF, ограничения частоты, защиты от подмены DNS для HTTP-клиента: Sprint 6.
- Результаты в памяти одного процесса (1 час); постоянное хранение, краткая и полная версия отчёта, учёт запусков и
  выгрузка для владельца обсуждены, но не решены: решение за владельцем продукта, в бэклог не внесено.
- Версия Chrome в bug report не записывается (поле окружения пока пустое).
- Остановка не прерывает идущий HTTP-запрос (PB-069); недоступный сайт стоит около 50 секунд (PB-068).
- Браузерное задание CI для последних коммитов спринта на момент закрытия не подтверждено.
