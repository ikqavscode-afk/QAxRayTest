# Sprint 4. План: вход, прогресс, детали

Статус: запланирован. Скорость для планирования: около 28 SP (Sprint 1: 26, Sprint 2: 31, Sprint 3: 28).

## Цель спринта

Закрыть все 25 проверок и сделать запуск управляемым: пользователь видит прогресс, может остановить запуск,
открывает результат по ссылке и смотрит детали каждой проверки.

## Выбранные задачи (28 SP)

| ID | Задача | SP |
|---|---|---|
| PB-030 | QC-017, QC-018, QC-019: вход и регистрация (только структура) | 7 |
| PB-031 | Фоновый запуск, прогресс, остановка (`RUNNING`, `STOPPED`) | 8 |
| PB-032 | Хранение запуска, POST/Redirect/GET | 5 |
| PB-033 | Страница деталей проверки (и убирает колонку «Подробности» из таблицы на узком экране) | 3 |
| PB-027 | Браузер уточняет `WARNING` проверок по HTML (QC-006, 007, 008, 011, 013) | 5 |

Порядок работы: PB-030 (на готовом порте), затем PB-032 и PB-031 (общая основа: идентификатор запуска, состояние),
затем PB-033, в конце PB-027.

## Критерии приёмки

- **PB-030:** проверки только читают структуру страницы (ссылка или форма входа, поля логина и пароля, кнопка отправки,
  метки; ссылка или форма регистрации); данные не вводятся и не отправляются, аккаунт не создаётся; нет форм: `SKIPPED`;
  результаты только `PASSED`, `WARNING`, `SKIPPED`; тексты страницы в отчёт не попадают.
- **PB-031:** запуск выполняется в фоне; этапы и прогресс (сколько проверок выполнено) видны на странице без перезагрузки
  вручную; остановка прекращает запуск между проверками, закрывает браузер и сторож, статус `STOPPED`;
  одновременно допускается ограниченное число запусков.
- **PB-032:** после отправки формы пользователь перенаправляется на адрес запуска; обновление страницы не повторяет
  запросы к сайту; запуски хранятся в памяти за интерфейсом хранилища (замена позже); срок хранения и лимит числа.
- **PB-033:** у каждой проверки своя страница: ожидаемое, фактическое, причина, доказательства; в таблице три колонки;
  правила [стандартов интерфейса](../standards/ui-ux-standards.md) соблюдены.
- **PB-027:** если страница строится скриптами и по HTML проверка дала `WARNING`, а браузер видит содержимое, результат
  уточняется; правила приоритета записаны в ADR.

## Решения, которые нужно принять на планировании

| Вопрос | Предложение |
|---|---|
| Что делать, если Chrome не найден | Браузерные проверки получают `SKIPPED` с причиной «Chrome не найден», а не `BLOCKED` (иначе консоль возвращает код 1 только из-за окружения); запись в ADR-0008 |
| Как выполнять запуск в фоне | Поток с общим состоянием запуска и опросом статуса страницей; полноценная очередь не нужна для MVP |
| Как остановить браузерную проверку посередине | Флаг остановки проверяется между проверками и между шагами браузерной пробы; закрытие браузера прерывает ожидание |
| Где хранить запуски | Память процесса за интерфейсом хранилища; срок 1 час, не более 50 запусков |
| Приоритет результатов (PB-027) | Браузерный результат уточняет, но не отменяет результат по HTML; оба видны в деталях |

## Риски

| Риск | Реакция |
|---|---|
| Потоки и общее состояние во Flask | Один объект хранилища с блокировкой, тесты на гонки остановки и завершения |
| Браузер и сторож не закрылись при остановке | Закрытие в `finally`, тест на остановку посреди запуска, проверка отсутствия процессов-сирот |
| Объём PB-031 больше 8 SP | Делим: состояние и опрос отдельно от остановки |
| Изменение формы результатов ломает тесты | Контракт результата (`RunReport`) не меняется, добавляется слой состояния запуска |
