# Sprint 5. План: отчёты

Статус: запланирован. Скорость для планирования: около 28 SP (Sprint 1: 26, Sprint 2: 31, Sprint 3: 28, Sprint 4: 28).

## Цель спринта

Результат запуска можно безопасно сохранить и передать: секреты замаскированы, для `FAILED` формируется черновик
bug report, есть Allure-совместимый отчёт, всё это скачивается из интерфейса и покрыто интеграционными тестами.

## Критерии приёмки

- **PB-070:** отсутствие Chrome определяется при первом обращении; браузерные проверки получают `SKIPPED` с причиной
  «Chrome не найден», `BLOCKED` остаётся для сбоев при работе браузера; код возврата консоли 0, если нет `FAILED`.
- **PB-040:** маскируются заголовки `Authorization` и `Cookie`, токены и ключи в параметрах адреса (`token`, `key`,
  `api_key`, `access_token`, `password`, `secret`, `session`), значения вида JWT и пары «ключ=значение» с такими именами;
  маскирование применяется к результатам до сохранения и к журналам; тесты на утечку секретов в каждом пути вывода
  (страница, JSON, консоль, bug report, Allure).
- **PB-041:** черновик содержит поля концепции (ID и заголовок, проект и адрес, окружение и браузер, предусловия и шаги
  воспроизведения, ожидаемое и фактическое, важность, частота, время запуска, доказательства), помечен «не
  подтверждено» (`FAILED` не всегда дефект, ADR-0002), текст экранируется, секреты замаскированы.
- **PB-042:** для каждой проверки файл `*-result.json` в формате Allure (имя, статус, время, шаги, вложения, метки);
  соответствие статусов записано в ADR; отчёт открывается в Allure (проверка на образце); архив `.zip`.
- **PB-045:** сетевой сбой на одном пути не блокирует остальные: результат формируется по каждому пути.
- **PB-043:** сквозные тесты «форма, фон, прогресс, остановка, отчёты» с имитированной сетью и заглушкой браузера,
  без обращений к внешним сайтам.
- **PB-044:** кнопки скачивания только у завершённого или остановленного запуска; имена файлов безопасны; страницы
  скачивания проходят стражей стандартов интерфейса.

## Решения, которые нужно принять на планировании

| Вопрос | Предложение |
|---|---|
| Соответствие статусов Allure | `PASSED` → passed, `FAILED` → failed, `BLOCKED` → broken, `SKIPPED` → skipped, `WARNING` → passed с меткой `warning` и описанием (в Allure нет такого статуса); запись в ADR-0012 |
| Скриншоты как доказательства | Не в Sprint 5: требуют маскирования изображений; в bug report пока строки и фрагменты (скриншоты вынести в запас) |
| Где применять `Redactor` | На границе: при сохранении результата в хранилище и при записи в журнал; а не внутри каждой проверки |
| Приоритет и частота воспроизведения в bug report | Приоритет не определяется (поле пустое), частота «1 запуск» до повторных запусков |
| Формат bug report | Markdown (читается человеком, копируется в трекер) и JSON |

## Риски

| Риск | Реакция |
|---|---|
| Неполное маскирование секретов | Белый список выводимых данных там, где можно; тесты «канарейка» с узнаваемыми секретами в каждом пути вывода |
| Неточное соответствие формату Allure | Проверка на образце Allure и сверка с документацией формата в начале PB-042 |
| Объём PB-043 | Начать с трёх сквозных сценариев, остальное по результатам |
