# Sprint 2. Проверки по HTML и API: итоги и ретроспектива

Период: 2026-11-07. Статус: завершён.

## Цель спринта

Расширить ядро: проверки по исходному HTML без браузера, подключение API (адрес документации,
базовый адрес, безопасные `GET`-пути), настройки и необязательные живые тесты.

## Что прошло хорошо

- Проверки по HTML и API добавлялись одной строкой в каталог, без правок исполнителя:
  принцип открытости/закрытости работает.
- Общий кэш запросов в контексте: каждый адрес запрашивается один раз для всех проверок.
- Эвристики честно говорят `WARNING` и отправляют в браузер, а не выдают ложный `FAILED`
  (страницы, строящиеся скриптами).
- Живой прогон на открытых сервисах для практики (около 26 целей) нашёл реальное ограничение:
  документированный ответ 201 давал ложный `FAILED`. Результат: ожидаемый статус для пути.
- Безопасность закреплена тестами: путь API не может сменить хост, параметры запроса (в них
  бывают токены) не попадают в отчёт, настройки не отключают политику адресов.

## Что мешало

- Кириллица в байтовых литералах снова вызвала синтаксическую ошибку; решение: тексты
  кодировать через `.encode()`.
- Часть шагов была внесена раньше красного прогона, и тест не показал, что именно ломается;
  правило: сначала тест и красный результат, потом код.
- Первый сценарий проверки редиректа на внутренний адрес оказался неверным: сам сервис для
  практики отвечает `403` на такие запросы. Живая проверка редиректов невозможна, она
  покрыта модульными тестами; DNS-вариант защиты проверен вживую.
- Потеря пробелов и строк при копировании кода, как и в Sprint 1; решение прежнее: форматировать
  командой `ruff format` и передавать файлы целиком.

## Уроки

1. Живой прогон по разным средам находит то, чего не видят заглушки; список целей держим вне репозитория.
2. Любое значение, влияющее на нагрузку чужих сайтов, ограничивается диапазоном, а не отключается.
3. Если сведений недостаточно (нет схемы, скрипты строят страницу), проверка говорит `SKIPPED`
   или `WARNING` с причиной, а не `PASSED`.

## Технический долг

См. [ADR-0003](../decisions/0003-dns-rebinding-and-known-risks.md) (DNS rebinding, CSRF, ограничение
частоты, синхронный запуск, маскирование секретов) и [ADR-0005](../decisions/0005-api-checks-and-contract-reading.md).
Дополнительно:
- Сетевой сбой на одном `GET`-пути блокирует все проверки по путям; нужен результат по каждому пути отдельно.
- Документация читается только в JSON; YAML и внешние `$ref` не поддерживаются.
- Лимит чтения тела 1 МБ: крупные описания API (например, у больших сервисов) дают `SKIPPED`.
- Нулевые счётчики `FAILED` и `WARNING` на странице результатов окрашены; результат не сохраняется
  (нужны POST/Redirect/GET и хранилище запусков); нет значка сайта (`favicon`).
- Живая проверка редиректов на внутренние адреса недоступна без своего тестового сервера.

## План Sprint 3

Цель: браузерные проверки и управляемый запуск.
- QC-012: доступность до 10 внутренних ссылок по `GET`, только тот же домен.
- Порт `BrowserPort` и адаптер Selenium; явные ожидания, лимиты, повтор только сетевых сбоев (ADR-0002).
- Браузерные проверки QC-009, QC-010, QC-014…QC-019; результат браузера уточняет `WARNING`
  проверок по исходному HTML (QC-006, QC-007, QC-008, QC-011, QC-013).
- Фоновый запуск с прогрессом и остановкой (статусы `RUNNING`, `COMPLETED`, `STOPPED`).
- Настройка CI для браузерных тестов (отдельное задание, не блокирует быстрые тесты).
