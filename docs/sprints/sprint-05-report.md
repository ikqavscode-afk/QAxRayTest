## Что получилось (обзор)

- **Маскирование** ([ADR-0011](../decisions/0011-secret-redaction.md)): секреты скрываются в хранилище, консоли, страницах и журналах.
  Правила проверены на враждебных входах, худший случай 0,6 с.
- **Bug report**: по одному черновику на каждый `FAILED`, статус «не подтверждено», приоритет пуст, разметка экранируется.
- **Allure** ([ADR-0012](../decisions/0012-allure-results.md)): архив собран настоящим Allure Report, статистика совпала с ожидаемой.
- **Устойчивость API-проверок**: сетевой сбой на одном пути больше не блокирует остальные.
- **Сквозные тесты**: полный запуск, остановка посреди работы, запрещённый адрес и отсутствие Chrome; без обращений
  к внешним сайтам.

## Препятствия и риски

| Что | Состояние |
|---|---|
| GitHub Push Protection заблокировал пуш из-за выдуманного токена в тесте | Решено: строки собираются из частей, правило в `check_content.py`, тест-страж; блокировка не обходилась |
| «Запушил» не означало, что коммиты ушли | Решено: после каждого пуша сверяются `origin/main` и `HEAD` |
| Квадратичное время двух правил маскирования (ReDoS) | Найдено проверкой и исправлено |
| Четыре коммита (PB-041, PB-042, PB-045 и PB-043 после коммита) не на GitHub | Нужен пуш |
| Открытые долги: защита форм от подделки запросов (CSRF), ограничение частоты, подмена DNS, остановка не прерывает идущий HTTP-запрос, недоступный сайт отвечает ~50 с, результаты только в памяти | В план Sprint 6 |

## Что улучшить (наблюдения для ретроспективы)

1. Выдуманные «секреты» в тестах тоже срабатывают у сканеров: сразу собирать их из частей.
2. Каждое новое регулярное выражение сразу проверять на враждебных входах.
3. Подтверждать пуш сверкой с `origin/main`, а не словами.
4. Сквозные тесты дешевле и надёжнее с имитированными краями (сеть, браузер), чем с живыми сайтами.
