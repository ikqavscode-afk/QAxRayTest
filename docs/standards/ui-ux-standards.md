# Стандарты интерфейса, доступности и юзабилити

Эти стандарты обязательны для интерфейса самого приложения и служат опорой для эвристик
проверок (QC-008, 010, 014, 015, 016 и будущие). Решение: [ADR-0006](../decisions/0006-ui-ux-standards.md).
Автоматические стражи: `tests/unit/test_ui_standards.py`.

## 1. Доступность (WCAG 2.2, уровень AA)

| Требование | Как применяем | Как проверяем |
|---|---|---|
| Контраст обычного текста не ниже 4,5:1 (1.4.3) | Цвета в переменных CSS; подсказки внутри полей (`placeholder`) окрашены явно | Тест считает контраст всех цветов текста на обеих поверхностях |
| Контраст крупного текста и элементов интерфейса не ниже 3:1 (1.4.11) | Границы полей `--border-control` (отдельно от декоративных линий) | Тест контраста границ и цвета фокуса |
| Клавиатура: всё доступно через `Tab`, фокус виден (2.1.1, 2.4.7) | Единое правило `:focus-visible` (3 px, смещение 2 px), `outline` не убирается; прокручиваемая таблица получает фокус и имя | Тесты правила фокуса и области прокрутки; ручная проверка клавишей `Tab` |
| Размер цели нажатия: минимум WCAG AA 24×24 (2.5.8); в проекте строже: **не менее 44×44 px** | Кнопки, ссылки-кнопки, метка чекбокса, `summary`, ссылка-бренд: `min-height: 2.75rem` | Тест правил CSS; замер в браузере на 375 px |
| Масштабирование и перестройка (1.4.4, 1.4.10) | `viewport` без запрета масштаба, базовый шрифт 16 px, нет горизонтального переполнения страницы | Тест разметки; замер `scrollWidth` в браузере на 375 и 1280 px |
| Семантика и ARIA | Правильные теги (`label`, `fieldset`, `table`, `caption`, `th scope`), `lang="ru"`, `aria-invalid`, `role="alert"` у ошибок, статус словом, не только цветом | Тесты веб-интерфейса |

## 2. Юзабилити

### 10 эвристик Нильсена

| Эвристика | Состояние в продукте |
|---|---|
| Видимость статуса системы | Статус каждой проверки словом; прогресс запуска и остановка: Sprint 4 (PB-031) |
| Соответствие реальному миру | Понятные русские названия и причины, словарь статусов в ADR-0002 |
| Свобода и контроль пользователя | Кнопка «Новая проверка»; отмена запуска: Sprint 4 |
| Согласованность и стандарты | Один словарь статусов, одни компоненты, один набор переменных CSS |
| Предотвращение ошибок | Подтверждение права, валидация адресов и путей, лимиты, запрет внутренних адресов |
| Узнавание вместо вспоминания | Подсказки у каждого поля, примеры в `placeholder` |
| Гибкость и эффективность | Веб-форма и консоль с теми же параметрами |
| Минимализм | Один экран ввода, необязательные поля API в отдельной группе |
| Помощь в исправлении ошибок | Сообщение рядом с полем с описанием, что исправить; введённое сохраняется |
| Справка | Подсказки и README; отдельная справка в MVP не нужна |

### ISO 9241-110

Пригодность для задач (один сценарий «адрес, проверки, результат»), самоописываемость
(подсказки, статусы словами), соответствие ожиданиям (одинаковое поведение форм и консоли),
обучаемость (примеры), управляемость (остановка в Sprint 4), устойчивость к ошибкам
(валидация, сохранение ввода).

### Законы Фиттса и Хика
Основное действие («Запустить проверки») крупное и единственное первичное; на экране не более
одного выбора действия, необязательные поля свёрнуты в отдельную группу; зоны нажатия от 44 px.

## 3. Адаптивность и сетка

| Правило | Применение |
|---|---|
| Колонки: 12 (от 1200 px), 8 (768 px), 4 (360–390 px) | Интерфейс одноколоночный с максимальной шириной 56 rem; при добавлении сетки использовать эти брейкпоинты |
| Отступы по сетке 8 pt (допустимо 4 px) | Все `padding`, `margin`, `gap` кратны 4 px; тест перебирает значения в CSS |
| Размеры окна для проверок | 1280 px (рабочий стол) и 375 px (телефон), как в QC-010 |

## 4. Дизайн-системы

Готовые библиотеки компонентов не подключаются (нет лишних зависимостей), но берутся принципы:
Material 3: токены цвета и состояния (`focus`, `hover`, `disabled`), Apple HIG: чистая типографика
и крупные цели нажатия, Fluent 2: плотные таблицы данных. Состояния `hover` и `disabled` у кнопок
пока не описаны (PB-067).
