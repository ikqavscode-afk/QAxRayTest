# ADR-0015. Соединение с проверенным IP (защита от DNS rebinding)

Статус: принято. Дата: 2026-11-08.

## Контекст

`SafeHttpClient` проверял адрес политикой, а затем `requests` сам разрешал имя повторно. Между проверкой и
соединением DNS мог ответить иначе (rebinding): проверка видела публичный адрес, соединение шло на внутренний. Для
браузера это закрыто прокси-сторожем (ADR-0007), для HTTP-клиента оставалось открытым (ADR-0003).

## Решение

1. **Своё соединение** (`app/adapters/http/pinned.py`): в момент соединения имя разрешается один раз, все полученные
   адреса проверяются политикой (`TargetPolicy.public_addresses`), соединение устанавливается только с ними, по очереди.
   Любой непубличный адрес в ответе отклоняет весь ответ (`TargetRejectedError`), сокет не открывается.
2. **Имя остаётся в запросе:** заголовок `Host`, SNI и проверка сертификата идут по имени хоста, адрес подставляется
   только в сокет. Для HTTPS ничего не ослабляется.
3. **Подключение:** `PinnedAdapter` для `http://` и `https://`; сессия по умолчанию (`pinned_session`) создаётся клиентом,
   если сессия не передана. Тесты с `responses` передают свою сессию и сеть не используют.
4. **Прокси из окружения не используются** (`trust_env=False`): прокси обошёл бы проверку адреса назначения. Если
   понадобится прокси, это отдельное решение с проверкой адреса прокси.
5. **Прежние проверки остались:** адрес проверяется до первого запроса и на каждом перенаправлении; новая проверка при
   соединении закрывает окно между ними.

## Проверено

- Модульные тесты: соединение идёт на проверенный IP; повторного разрешения нет; смешанный ответ отклоняется;
  подмена ответа между проверкой и соединением отклоняется без открытия сокета; переход к следующему адресу;
  тайм-аут; сессия не берёт прокси из окружения; боевой клиент использует адаптеры.
- Настоящее соединение с локальным сервером: имя отсутствует в DNS, но запрос доходит до проверенного IP с исходным
  заголовком `Host`; при смене ответа на внутренний адрес сервер соединения не видит.
- Вживую: `https://example.com/` и `http://example.com/` отвечают 200 (сертификат и SNI работают), `localhost` и
  `127.0.0.1` отклонены, сертификат с истёкшим сроком не принят.

## Последствия

Остаточный риск: адрес проверяется на момент соединения; закреплённое keep-alive соединение живёт, пока его держит пул
(тот же проверенный адрес). Каждый запрос ходит новым разрешением имени при новом соединении; кэширования DNS нет.
