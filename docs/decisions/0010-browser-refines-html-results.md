# ADR-0010. Браузер уточняет результаты проверок по исходному HTML

Статус: принято. Дата: 2026-11-07.

## Контекст

Проверки QC-006, QC-007, QC-008, QC-011 и QC-013 анализируют исходный HTML без выполнения скриптов. Если страницу
строят скрипты (SPA), они честно дают `WARNING` «проверьте в браузере», хотя пользователь видит нормальную страницу.
С появлением браузерного порта (Sprint 3) эту проверку можно выполнить автоматически.

## Решение

1. **Когда уточняем.** Только если по исходному HTML получился `WARNING` и к запуску подключён браузер. Результаты
   `PASSED`, `FAILED` и `SKIPPED` по HTML не пересматриваются (браузер для них не используется и не запускается).
2. **Что берём из браузера.** Один снимок отрисованной страницы на запуск (проба `rendered_page`, общий кэш контекста):
   заголовок, `lang`, объём видимого текста, число видимых изображений и графики, адреса ссылок (до 50), наличие
   навигации. Перед снимком выполняется явное ожидание (до 3 с), пока появится заголовок и видимый текст; если страница
   так и не «успокоилась», берётся то, что есть. Тексты и ссылки в отчёт не попадают, кроме заголовка (как и раньше).
3. **Итоговый вердикт даёт отрисованная страница, но оба взгляда остаются видимыми:** «В браузере: … По исходному HTML: …».
   Статус по HTML сохраняется в доказательствах. Примеры: заголовок задан скриптом, `WARNING` → `PASSED`; навигации нет
   ни в HTML, ни в браузере, `WARNING` остаётся.
4. **Правила статусов.** Результаты уточнения остаются эвристиками (`PASSED`, `WARNING`, `SKIPPED`). Единственное
   исключение QC-007: страница пуста и в браузере (нет ни текста, ни изображений) даёт `FAILED`, как и пустая
   страница без скриптов по HTML.
5. **Если браузер недоступен или не смог открыть страницу,** остаётся результат по HTML, а в причине добавляется
   «уточнение в браузере не выполнено: …». Проверка не получает `BLOCKED`: результат по HTML сам по себе верен.
6. QC-012 и остальные проверки без `WARNING` по HTML не затрагиваются.

## Последствия

- На страницах, строящихся скриптами, итоги по QC-006…013 заметно честнее: меньше «проверьте вручную».
- Запуск такого сайта открывает Chrome раньше (при первой проверке с `WARNING`), а не только на QC-009; для обычных
  страниц без `WARNING` поведение и время не меняются.
- Асинхронно подгружаемое содержимое, которое появляется позже 3 секунд, останется незамеченным и даст `WARNING`
  или `FAILED` (для QC-007).
