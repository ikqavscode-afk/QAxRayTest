# ADR-0006. Стандарты интерфейса и доступности

Статус: принято. Дата: 2026-11-07.

## Контекст

Продукт сам проверяет доступность и вёрстку чужих сайтов (QC-008, 010, 014…016), значит его
собственный интерфейс должен соответствовать тем же стандартам. Общепринятые ориентиры:
WCAG 2.2 AA, 10 эвристик Нильсена, ISO 9241-110, 12/8/4-колоночная сетка, шаг 8 pt, зоны
нажатия не меньше 44 px, принципы Material 3, Apple HIG и Fluent 2.

## Решение

1. Базовый уровень доступности: **WCAG 2.2 AA**. Зона нажатия в проекте строже минимума AA (24 px): **44 px**.
2. Юзабилити оцениваем по эвристикам Нильсена и ISO 9241-110; результаты сведены в
   [docs/standards/ui-ux-standards.md](../standards/ui-ux-standards.md).
3. Вёрстка: отступы кратны 4 px (основной шаг 8 px), проверка при ширине 375 и 1280 px.
4. Цвета, отступы и границы задаются переменными CSS (токены); границы полей отделены от декоративных линий.
5. Требования закреплены **автотестами** (`test_ui_standards.py`: контраст, фокус, зоны нажатия, сетка,
   масштабирование) и входят в определение завершённости изменений интерфейса.
6. Внешние библиотеки дизайн-систем в MVP не подключаются; берутся только принципы.
7. Эвристики проверок, опирающиеся на эти стандарты, дают `PASSED` или `WARNING`, не `FAILED`.

## Последствия

- Любое изменение стилей проходит стражей; нарушение стандарта ломает сборку, а не обнаруживается позже.
- Тест читает CSS простыми регулярными выражениями: при смене подхода к стилям (например, препроцессор)
  стражей нужно адаптировать.
- Автотесты не заменяют ручную проверку (скринридер, клавиатура); она остаётся в определении завершённости.
