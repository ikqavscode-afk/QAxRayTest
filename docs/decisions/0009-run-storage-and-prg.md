# ADR-0009. Запуски: фон, прогресс, остановка, хранение, POST/Redirect/GET

Статус: принято. Дата: 2026-11-07.

## Контекст

Результат проверки раньше показывался прямо в ответе на отправку формы. Обновление страницы повторяло отправку
и запускало проверки заново (лишняя нагрузка на чужой сайт), результат нельзя было открыть повторно.
Для фонового запуска и страницы деталей (Sprint 4) нужно состояние запуска с идентификатором.

## Решение

1. **POST/Redirect/GET.** После отправки формы сервер отвечает `303 See Other` на `/runs/<идентификатор>`;
   результат показывает `GET`. Обновление страницы только читает сохранённый результат.
2. **Идентификатор неугадываемый** (`secrets.token_urlsafe(16)`): адрес результата нельзя перебрать. Формат
   проверяется (`[A-Za-z0-9_-]{16,64}`); неизвестный, просроченный и неверный идентификатор дают страницу «Запуск не
   найден» со статусом 404.
3. **Статусы запуска:** `RUNNING`, `COMPLETED`, `STOPPED`, `FAILED` (внутренняя ошибка приложения, а не находка о
   сайте; в запись попадает только общий текст, подробности пишутся в журнал сервера). Отклонение адреса политикой
   запуск не создаёт: форма показывает ошибку у поля (`400`), запись удаляется.
4. **Хранилище за интерфейсом** (`Store`): сейчас `InMemoryRunStore` (память процесса, потокобезопасное).
   Срок хранения 1 час, не более 50 запусков. Работающие запуски не вытесняются; при нехватке места вытесняется
   самый старый завершённый; если все места заняты работающими, новый запуск отклоняется (`429`).
5. **Записи неизменяемые** (`RunRecord`, снимки): хранилище заменяет запись целиком, читатели не видят полу-обновлений.

## Фоновый запуск, прогресс и остановка (PB-031)

1. **Фон.** `RunManager.start` проверяет адрес политикой (ошибка у поля, запись не создаётся), создаёт запись
   `RUNNING` и запускает поток-демон; запрос не ждёт конца проверок.
2. **Прогресс.** Исполнитель сообщает отчёт на данный момент в начале (чтобы стало известно число проверок) и после
   каждой проверки; хранилище держит частичный отчёт, страница показывает полосу `<progress>` с подписью
   (`role="status"`, `aria-live="polite"`) и уже готовые результаты. Скрипт `run.js` опрашивает `/runs/<id>/status`
   (только статус и счётчики, без данных о цели) и обновляет страницу без перезагрузки; без JavaScript есть ссылка
   «Обновить страницу». Скрипт обращается только к своему серверу и не использует `innerHTML`/`eval`.
3. **Остановка.** `POST /runs/<id>/stop` ставит флаг; исполнитель проверяет его между проверками, а `RunControl`
   сразу закрывает браузер (прерывает загрузку страницы). Запуск получает статус `STOPPED` с частичным отчётом.
   Если остановка пришла, когда все проверки уже выполнены, запуск остаётся `COMPLETED`. Замер вживую: остановка
   на этапе браузерных проверок занимала 0,1–1,7 с; пока идёт HTTP-запрос к сайту, остановка ждёт его конца
   (до тайм-аута клиента). После остановки не остаётся ни драйверов, ни Chrome, ни портов сторожа.
4. **Ограничение одновременных запусков:** 2 (у каждого свой Chrome); третий получает `429`.

## Последствия

- Результаты теряются при перезапуске приложения и через час; это сознательный выбор для MVP (файл или база
  подключаются заменой `Store` без правок веб-слоя).
- Несколько процессов приложения не делят состояние (для MVP запускается один процесс).
- Жёсткий обрыв процесса приложения (сигнал `kill`) может оставить Chrome: штатная остановка и завершение этого не
  допускают, а при ручном обрыве его нужно закрыть вручную (замечено при ручной отладке).
- Остановка не прерывает уже идущий HTTP-запрос библиотеки `requests`: она ждёт его конца.
- Лимит 50 запусков и срок 1 час пока заданы в коде; вынести в настройки можно с ADR-0004 (с границами).
