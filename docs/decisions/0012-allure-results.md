# ADR-0012. Результаты в формате Allure

Статус: принято. Дата: 2026-11-07.

## Контекст

Концепция требует отчёт, который открывается в Allure Report. Нужно решить, как статусы приложения соотносятся со
статусами Allure, какие поля заполнять и как не пропустить секреты в файлы.

## Решение

1. **Модуль ядра** `app/core/reports/allure.py`: `build_allure_files` (имя файла -> содержимое) и `build_allure_archive`
   (тот же набор в `.zip`). Без Flask и без файловой системы: запись на диск и отдача — дело веба (PB-044).
2. **Соответствие статусов:**

   | Статус приложения | Статус Allure | Пояснение |
   |---|---|---|
   | `PASSED` | `passed` | |
   | `FAILED` | `failed` | находка о сайте |
   | `BLOCKED` | `broken` | проверку не удалось выполнить (запрет политики, сбой) |
   | `SKIPPED` | `skipped` | |
   | `WARNING` | `passed` + метка `warning` | у Allure нет предупреждения; запуск не краснеет, метка остаётся для фильтра |

   Причина и фактический результат попадают в `statusDetails.message`.
3. **Поля результата:** `uuid` и `historyId` (стабильные, из идентификатора проверки и адреса), `name`/`fullName`
   (`QC-001: Заголовок`), `start`/`stop` (подряд, по длительностям), метки `suite`, `feature` (адрес), `story`
   (идентификатор проверки), `severity` (HIGH→critical, MEDIUM→normal, LOW→minor), описание «ожидалось/фактически»,
   доказательства как шаги. Файл `environment.properties`: версия приложения, система, сайт, Chrome при наличии.
4. **Безопасность.** Все тексты идут через `Redactor`. Имена файлов строятся только из UUID. Архив содержит файлы без
   каталогов и без `..`. Вывод детерминирован (фиксированная дата в архиве), поэтому его удобно проверять тестами.
5. **Проверка на образце.** Архив распакован и собран реальным Allure Report: статистика совпала (failed, broken, skipped,
   passed ×2). Тест «канарейкой» подтверждает отсутствие секретов в файлах и в архиве.

## Последствия

Вложения (скриншоты) не создаются: браузерные доказательства пока текстовые. Скачивание из интерфейса — PB-044.
