# ADR-0007. Браузер: Selenium, прокси-сторож, лимиты

Статус: принято. Дата: 2026-11-07.

## Контекст

Для браузерных проверок нужно открывать чужие страницы в Chrome. Страница чужого сайта сама решает,
куда обращаться (редиректы, картинки, скрипты), поэтому без защиты она может заставить браузер
на нашем компьютере обратиться к внутренней сети (SSRF через браузер).

## Решение

1. **Selenium + Chrome за портом `BrowserPort`.** Ядро не импортирует Selenium. Драйвер подбирает и
   загружает Selenium Manager при первом запуске (из интернета, в кэш `~/.cache/selenium`).
   Режим окна: по умолчанию без видимого окна (`--headless=new`), видимое включается `QAXRAY_BROWSER_HEADLESS=0`.
2. **Прокси-сторож** (`guard_proxy.py`). Chrome запускается с `--proxy-server` на локальный сторож
   (только `127.0.0.1`, свободный порт) и `--proxy-bypass-list=<-loopback>`, поэтому через сторож идёт
   всё, в том числе обращения к `localhost`. Сторож для каждого соединения:
   - разрешает имя, проверяет все ответы DNS политикой адресов и **соединяется с проверенным IP**,
     а не по имени (подмена DNS между проверкой и соединением невозможна);
   - пропускает только порты 80 и 443, HTTPS-туннели (`CONNECT`) и обычные `GET`/`HEAD`;
   - отклоняет остальное: `403` (политика, порт), `405` (метод), `400` (разбор), `502`, `503` (лимит);
   - ограничивает число соединений (64), простой (15 с) и общий трафик (100 МБ);
   - ведёт список заблокированных `хост:порт` без путей и параметров запроса.
3. **Навигация.** Адрес проходит политику до открытия страницы; допустимы только `http` и `https`
   (`file:`, `chrome:` и др. отклоняются). Ошибка политики или сторожа даёт `BrowserBlockedError`
   без повторов.
4. **Скачивание запрещено** (`download_restrictions: 3`, папка загрузок временная, удаляется при закрытии),
   профиль Chrome временный, расширения, синхронизация, фоновые обращения и WebRTC-утечки выключены.
5. **Точная ширина окна.** Headless-Chrome не сужает окно меньше 500 px, поэтому размер задаётся
   эмуляцией `Emulation.setDeviceMetricsOverride` (замер: 375 px действительно 375).
6. **Страницы ошибок Chrome.** Ошибки сертификата и сети показываются как обычная страница, поэтому
   они распознаются по разметке (`.interstitial-wrapper`, `#error-code`): сертификат даёт
   `BrowserCertificateError` (без повторов), остальное `BrowserNetworkError`.
7. **Лимиты и стабильность** (ADR-0002): явные ожидания (`WebDriverWait`, без `sleep`), тайм-аут страницы
   `QAXRAY_BROWSER_PAGE_TIMEOUT` (5–60 с, по умолчанию 20), не более 6 открытий и 90 с браузера на
   запуск, повтор только сетевых сбоев (до 2 раз), браузер запускается лениво и закрывается всегда.
8. **Любой сбой браузера** (`BrowserError`) даёт `BLOCKED`, а не `FAILED`.

## Проверено вживую (Chrome 156)

Прямая навигация на `127.0.0.1`, `localtest.me`, `169.254.169.254` и `file://` отклонена; JavaScript
страницы пытался обратиться к реальному локальному серверу: сервер получил **0 соединений**; просроченный
сертификат распознан; скачивание ничего не сохранило; драйвер-сирот после закрытия нет.
Закреплено автотестами `tests/browser` (включаются `QAXRAY_BROWSER=1`).

## Ограничения и риски

- Внутри HTTPS-туннеля сторож видит только адрес, но не метод: запись (`POST`) в публичный сайт из
  его собственных скриптов не блокируется. Мы не отправляем формы и не нажимаем кнопки отправки.
- Сайты на портах кроме 80 и 443 в браузере недоступны (`BLOCKED`).
- Закрытие сторожа и браузера выполняется при завершении запуска; жёсткий обрыв процесса может оставить
  временную папку и процесс драйвера (их стоит закрывать при остановке запуска, Sprint 4).
- Браузерные тесты нестабильны по природе (сеть, версия Chrome): они выключены по умолчанию и
  запускаются отдельным заданием (PB-028).

## Последствия

- Риск DNS rebinding из [ADR-0003](0003-dns-rebinding-and-known-risks.md) для браузера закрыт; для
  HTTP-клиента остаётся (PB-052).
- Каждая браузерная проверка добавляет пробу в порт и в заглушку, а не обращается к Selenium напрямую.
