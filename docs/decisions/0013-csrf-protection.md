# ADR-0013. Защита от подделки межсайтовых запросов (CSRF)

Статус: принято. Дата: 2026-11-08.

## Контекст

Форма запуска (`POST /check`) и остановка (`POST /runs/<id>/stop`) меняют состояние сервера. Чужая страница может
заставить браузер пользователя отправить такой запрос: запустить проверки от его имени или остановить его запуск.
Аккаунтов в приложении нет, поэтому важны именно запуск и расход ресурсов.

## Решение

1. **Токен в сессии.** Модуль `app/web/csrf.py`. Токен (32 случайных байта, URL-безопасный текст) хранится в подписанной
   cookie сессии `qaxray_session` (`HttpOnly`, `SameSite=Lax`) и вставляется скрытым полем `csrf_token` в каждую форму.
2. **Проверка** для всех методов, кроме `GET`, `HEAD`, `OPTIONS`: токен из формы сравнивается с токеном сессии
   постоянным по времени сравнением; пустой, слишком длинный или чужой токен даёт 403.
3. **Заголовок Origin.** Если он есть и не совпадает с хостом запроса (в том числе `null`), запрос отклоняется даже с
   верным токеном. Если заголовка нет, решает токен.
4. **Ответ при отказе:** страница `csrf_rejected.html` с кодом 403: ничего не выполняется, введённые данные не
   выводятся, есть ссылка на форму.
5. **Ключ подписи** создаётся при запуске процесса (`secrets.token_bytes`) и нигде не сохраняется. После перезапуска
   старые страницы получают отказ и просят открыть форму заново. Это согласуется с хранением запусков в памяти одного
   процесса; для нескольких процессов потребуется общий ключ (отдельное решение).
6. **Отключение** только явной настройкой приложения `CSRF_ENABLED=False` (используется в модульных тестах, не
   настраивается переменными окружения). Сквозные тесты идут с включённой защитой.

## Проверено

Модульные тесты: отказ без токена, с неверным токеном, с токеном другой сессии, без cookie, с чужим Origin; успех с
верным токеном и многократное использование; GET без токена; флаги cookie. Сквозные тесты проходят форму как браузер.
Вручную в браузере: форма отправляется, запрос без токена при наличии cookie сессии получает 403.

## Последствия

- Cookie без флага `Secure`, чтобы работало по `http://` локально. При публикации по HTTPS нужен `Secure`
  (задача публикации, PB-054).
- Защита не заменяет ограничение частоты (PB-051): вручную отправленная форма по-прежнему может запускать проверки.
