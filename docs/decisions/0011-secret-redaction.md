# ADR-0011. Маскирование секретов (Redactor)

Статус: принято. Дата: 2026-11-07.

## Контекст

Результаты проверок, доказательства, сообщения об ошибках и журналы могут содержать секреты: токены и ключи в
параметрах адреса, заголовки `Authorization` и `Cookie`, пароли в JSON, логин и пароль в адресе. Концепция требует,
чтобы секретов не было в журналах и отчётах. Отчёты (bug report, Allure) только добавляют новые пути вывода.

## Решение

1. **Чистый модуль в ядре** (`app/core/security/redactor.py`): `Redactor.redact_text`, `redact_result`, `redact_report`.
   Значение заменяется на `***`, структура и остальной текст сохраняются; результаты возвращаются копиями.
2. **Что маскируется** (без учёта регистра): заголовки `Authorization`, `Proxy-Authorization`, `Cookie`, `Set-Cookie`,
   `X-Api-Key`, `X-Auth-Token` (до конца строки); значения параметров и полей с именами `token`, `access_token`,
   `refresh_token`, `id_token`, `api_key`, `key`, `secret`, `client_secret`, `password`, `passwd`, `pwd`, `session`,
   `sid`, `auth`, `signature`, `sig`, `credentials` и др. в адресе, фрагменте, `имя=значение`, `имя: значение`, JSON и
   словарях; `Bearer`/`Basic`-токены; JWT; логин и пароль внутри адреса (`https://user:pass@host`); известные форматы ключей
   (AWS, GitHub, Slack, Google, `sk-`); блоки закрытых ключей. Лишнее маскирование предпочтительнее пропуска.
3. **Где применяется (на границах, а не внутри проверок):**
   - `RunManager`: каждый отчёт (в том числе промежуточный) маскируется до записи в хранилище; страницы, JSON статуса
     и (в будущем) скачиваемые отчёты читают только уже замаскированные данные;
   - консоль: отчёт маскируется перед печатью;
   - страницы: адрес сайта выводится через фильтр `redact`;
   - журналы: единый обработчик с `RedactingFormatter` маскирует итоговую строку, включая трассировку ошибки
     (`configure_logging` вызывается консолью и фабрикой веб-приложения, повторный вызов безопасен).
4. **Производительность.** Правила проверены на враждебных входах (200 тысяч символов): худший случай 0,6 с. Две
   квадратичные уязвимости, найденные при проверке (правило `схема://` и повторяющееся начало закрытого ключа), исправлены
   (привязка к началу схемы, ограничение длины тела ключа, включение правил только при наличии «PRIVATE KEY»);
   охранные тесты закреплены.
5. **«Канарейки».** `tests/unit/canary.py` содержит узнаваемые секреты в девяти формах и функцию `assert_no_secrets`;
   каждый путь вывода обязан её пройти (хранилище, страница результата, страница проверки, JSON статуса, адрес сайта,
   консоль, журнал). Новые пути (bug report, Allure) добавляют свой тест в тот же набор.

## Ограничения

- Секрет без признака (параметр с нейтральным именем, например `p=пароль`, или «голая» случайная строка) не распознаётся.
- Электронные адреса и другие персональные данные не маскируются (это не секреты); отчёты их и не собирают.
- Хвост закрытого ключа длиннее 8 КиБ без строки `END` маскируется только на этом объёме (ключи такого размера не встречаются).
- Слишком общие имена (`key`, `auth`, `sig`) могут дать лишнее маскирование, например `sort_key=1` превратится в `sort_key=***`.
- Тексты в журналах сторонних библиотек проходят маскирование только через наш обработчик.

## Последствия

- Секреты не доходят до хранилища и страниц даже при ошибке в конкретной проверке: страховка на границе.
- Добавляя новый путь вывода, нужно либо читать из хранилища, либо применить `Redactor`, и добавить «канарейку».
