# ADR-0002. Словарь статусов и правила стабильности

Статус: принято. Дата: 2026-11-07.

## Словарь статусов проверки

| Статус | Значение | Причина обязательна |
|---|---|---|
| `PASSED` | Проверка выполнена, ожидание подтверждено | нет |
| `FAILED` | Проверка выполнена, ожидание нарушено; возможен дефект | нет (есть фактический результат) |
| `WARNING` | Эвристика заметила возможную проблему; нужен взгляд человека | да |
| `SKIPPED` | Проверка неприменима (нет формы, нет схемы и т. п.) | да |
| `BLOCKED` | Проверка не смогла выполниться: сеть, тайм-аут, сбой браузера, цель запрещена политикой | да |

Правила:
- Неприменимый сценарий получает `SKIPPED`, а не `FAILED`.
- Сбой среды получает `BLOCKED`, а не `FAILED`. `FAILED` не всегда подтверждённый дефект,
  поэтому bug report помечается как черновик со статусом подтверждения.
- Эвристические проверки никогда не дают `FAILED`: только `PASSED` или `WARNING`.
- Статус `ERROR` из концепции в коде не используется; его роль выполняет `BLOCKED`.

## Статус запуска

`RUNNING`, `COMPLETED`, `STOPPED` (остановлен пользователем), `REJECTED` (цель не прошла политику
безопасности, проверки не начинались).

## Правила стабильности браузерных и сетевых проверок

1. Только явные ожидания (`WebDriverWait`); `sleep` запрещён.
2. Лимиты: на одну проверку, на весь запуск, на число ссылок и размер ответа; значения в конфигурации.
3. Повтор только при сетевых сбоях (тайм-аут, обрыв соединения), не более 2 раз.
   Нарушение ожидания и «элемент не найден» не повторяются.
4. Если повторы не помогли, результат `BLOCKED` с причиной.
5. Сбой одной проверки не останавливает запуск.
6. Каждое действие в браузере ограничено: навигация только по разрешённым адресам, без загрузок
   и доступа к файлам.
