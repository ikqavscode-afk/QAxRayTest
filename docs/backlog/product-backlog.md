# Продуктовый бэклог QAxRayTest

Цель продукта: расширяемая платформа безопасного базового тестирования сайтов и API
(стандартный профиль из 25 проверок, понятные результаты, черновики bug report, Allure-отчёт).
Правила работы с бэклогом: [docs/process/scrum.md](../process/scrum.md).

Обозначения: статус ✅ готово, 🔜 запланировано, ⬜ в запасе; приоритет по MoSCoW;
очки (SP) по шкале Фибоначчи. Очки Sprint 0–2 выставлены задним числом.

## Состав MVP (по концепции) и прогресс

| Пункт MVP | Статус |
|---|---|
| Три поля адресов, валидация, подсказки | ✅ |
| Подтверждение права на тестирование | ✅ |
| Один профиль из 20–30 проверок | ✅ 25 из 25 |
| Ограниченные браузерные проверки | ✅ (Sprint 3) |
| Безопасные API-проверки по `GET` | ✅ |
| Тайм-ауты и ограничения ресурсов | ✅ |
| Сводка и детали каждой проверки | ✅ (Sprint 4) |
| Черновики bug report для `FAILED` | ✅ (Sprint 5) |
| Allure-совместимый отчёт | ✅ (Sprint 5) |
| README, пример конфигурации, тесты приложения | ✅ (финал в Sprint 6) |

## Риски

| Риск | Что делаем |
|---|---|
| Нестабильность браузерных проверок и запуск браузера в CI | Явные ожидания, лимиты, отдельное задание CI, браузерные тесты не блокируют быстрые |
| Фоновый запуск и состояние во Flask | Простое хранилище в памяти и ADR перед реализацией; хранилище за интерфейсом |
| Неизвестный формат Allure | Сначала короткое исследование в начале Sprint 5 |
| Запросы к чужим сайтам | Политика адресов, лимиты, пауза между запусками, цели вне репозитория |
